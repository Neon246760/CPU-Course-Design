# 计组与汇编实训：中期、最终汇报范围划分

## 1. 划分目的与总原则

本项目同时服务于“计算机组成原理课程设计”和“汇编与接口技术课程设计”。两门课程可以共用同一套 EES-338 计算机系统和最终演示，但报告、PPT 和答辩必须突出不同的设计对象，避免把同一项成果在两门课程中重复计分。

建议采用以下两条主线：

- **计组主线：**设计、实现并验证一颗基于水平微码控制的 RV32I 五级流水 CPU；中期证明基础流水线正确，最终加入附加功能、性能对比和 FPGA 下板结果。
- **汇编与接口主线：**设计可复用的 ST7571 LCD SPI 接口控制器，通过 MMIO 与 CPU 连接，并用 RISC-V 汇编实现驱动和俄罗斯方块应用；中期证明接口控制器与基础驱动正确，最终证明 IP 封装、软硬件集成和实板应用正确。

两门课程的边界如下。

| 内容 | 计组归属 | 汇编与接口归属 |
|---|---|---|
| RV32I 指令、微码控制、五级流水数据通路 | 核心内容 | 作为软件运行平台简述 |
| 前递、load-use 停顿、分支冲刷、存储等待 | 核心内容 | 只说明 MMIO 写会让 CPU 等待 |
| 溢出、中断、Cache、分支预测 | 计组附加功能 | 不作为汇编课程主要成果 |
| 单周期 CPU 对比、CPI/IPC/MIPS/CPU 时间 | 计组重点 | 不展开 |
| LCD SPI 协议、初始化状态机、发送握手 | 作为板级观察通道简述 | 核心内容 |
| LCD 控制器封装为独立 IP | 不作为计组创新点 | 核心提交物和复用证据 |
| MMIO 寄存器、LCD 汇编驱动 | 说明系统能访问外设 | 核心内容 |
| 俄罗斯方块算法和汇编实现 | 作为整机演示结果简述 | 核心软件成果 |
| LED、UART、LCD、蜂鸣器实板现象 | 证明整机闭环 | 分别证明接口和应用效果 |

`docs/实训说明.txt` 中要求“硬件类实训包含两门课程，内容和计分项没有重叠”。答辩时应明确说：同一块开发板承载两个成果，计组评价 CPU，汇编课程评价 LCD 接口控制器及其汇编驱动和应用。

## 3. 计组中期汇报范围

### 3.1 汇报目标

中期只回答一个问题：**不依赖附加功能，这颗基础五级流水 CPU 是否已经能够正确执行程序，并正确处理流水线相关？**

中期不讲单周期 CPU 性能对比，不讲 Cache、动态分支预测、中断和溢出异常，也不把下板结果作为主要内容。可以在最后一页列为下一阶段计划，但不提前展开结果。

### 3.2 应讲内容

1. **任务要求和选型**
   - 选择 RV32I 教学子集，基础实现为 27 条指令，超过 16 条要求。
   - 指令覆盖运算、传送和控制三类。
   - 采用经典 IF、ID、EX、MEM、WB 五级流水。
   - 采用水平微码控制与硬布线流水线仲裁相结合的控制结构。

2. **基础指令系统**
   - 算术与逻辑：`ADD/SUB/ADDI/AND/OR/XOR/ANDI/ORI/XORI`。
   - 移位与比较：`SLL/SRL/SRA/SLT/SLTU`。
   - 传送与访存：`LUI/AUIPC/LW/SW/LB/LBU/SB`。
   - 控制转移：`BEQ/BNE/BLT/BGE/JAL/JALR`。
   - 只需展示分类、典型编码和控制行为，不必逐条念完控制字。

3. **微程序控制器**
   - `opcode/funct` 在 ID 级映射到微地址。
   - 微码 ROM 输出水平控制字，控制 ALU、操作数选择、访存、写回、分支等行为。
   - 控制字段随指令进入流水寄存器。
   - 强调“微码决定指令做什么，流水线控制器决定何时推进、暂停或清除”。

4. **五级流水数据通路**
   - IF：PC 选择和取指请求。
   - ID：译码、寄存器读取、立即数生成、微码查询。
   - EX：ALU、地址计算、分支判定。
   - MEM：加载/存储和存储器握手。
   - WB：结果写回和指令退休。
   - 说明四组流水寄存器及 `valid` 位的作用。

5. **三类流水线相关**
   - 数据相关：EX/MEM 和 MEM/WB 前递，优先选取最新结果；`rd=x0` 不参与前递。
   - load-use：保持 PC 与 IF/ID，向 ID/EX 插入一个气泡，数据可用后继续。
   - store-data：把最新结果前递到存储写数据端，避免写入旧值。
   - 结构相关：指令和数据接口分离；存储器无法立即响应时由握手信号冻结有关流水级。
   - 控制相关：EX 级得到真实分支结果，错误路径清除 IF/ID 和 ID/EX，PC 跳到正确地址。

6. **基础验证方法**
   - testbench 不只看波形，还自动检查寄存器、内存、退休计数和最终 PASS。
   - 单元测试验证译码、立即数、ALU 等模块。
   - `tb_cpu_core` 验证整颗基础 CPU。
   - 展示一段综合程序，从取指到最终写回形成闭环。

### 3.3 中期必须准备的波形

建议只放四张可解释的关键波形，每张图用箭头标出触发条件和结果。

| 波形 | 建议观察信号 | 必须说明的现象 |
|---|---|---|
| 正常流水推进 | `pc`、各级 `valid`、各级 `instr`、`retire_valid` | 多条指令同时处于不同流水级，填充后连续退休 |
| ALU 前递 | `id_ex.rs*`、`ex_mem.rd`、`mem_wb.rd`、`forward_a/b`、ALU 输入/结果 | 后继指令不等待寄存器写回即可获得最新结果 |
| load-use 停顿 | `stall_data`、PC、IF/ID、ID/EX valid、写回值 | PC 和 IF/ID 保持，ID/EX 插入气泡，最终结果正确 |
| 分支冲刷 | `branch_taken`、`branch_mispredict/redirect`、`flush`、PC、各级 valid | 两条年轻错误路径指令被作废，没有寄存器或内存副作用 |

## 4. 计组最终汇报范围

### 4.1 汇报目标

最终汇报回答三个问题：

1. 基础流水 CPU 上增加了哪些附加功能，它们怎样与流水线正确协同？
2. 与大三单周期 CPU 相比，流水线设计在哪些指标和负载上更好，代价是什么？
3. 设计是否在真实 FPGA 上形成了从 CPU、存储器到外设的完整运行闭环？

基础流水结构只需用一至两页回顾，把主要时间留给新增工作和实测证据。

### 4.2 四项附加功能

1. **有符号溢出与异常**
   - `ADD/SUB/ADDI` 在 EX 级检测有符号溢出。
   - 故障指令不提交，年轻指令被清除，PC 转到 `mtvec`。
   - `mepc`、`mcause` 保存恢复信息，处理程序以 `MRET` 返回。
   - 展示正负边界测试和错误路径溢出不会触发的波形。

2. **外部中断**
   - 异步输入经双触发器同步并锁存 pending。
   - 在安全指令边界接受；更老的访存必须先完成。
   - 同步异常优先于中断，中断优先于普通重定向。
   - 展示 Cache/存储等待期间中断先 pending、之后进入并正确返回的波形。

3. **I-Cache 与 D-Cache**
   - 各 1 KiB、直接映射、16 B Cache 行。
   - I-Cache 缺失时按 4 个字整行填充。
   - D-Cache 写直达、写不分配；MMIO 旁路 Cache。
   - 展示冷缺失、同行命中、冲突替换、字节写和 MMIO bypass。

4. **动态分支预测**
   - 16 项 BTB 保存目标，BHT 使用 2 位饱和计数器预测方向。
   - IF 级预测，EX 级确认；误预测时恢复正确 PC 并清除错误路径。
   - 预测器只由未被取消的真实控制指令更新一次。
   - 128 次循环中，开启预测后错误数从 128 次降至 2 次；P-CACHE/P-FULL 周期从 670 降至 418。

### 4.3 单周期 CPU 性能对比

必须先说明公平性：使用组内成员大三阶段的真实单周期 RTL 和原始机器码；同一测试在六种配置中使用相同指令和输入；每组检查退休序列、写回、存储事件以及最终寄存器和内存。

课程指定指标和补充指标如下。

| 指标 | 用途 |
|---|---|
| CPI、IPC | 反映每条退休指令所需周期和单位周期吞吐 |
| MIPS、CPU 时间 | 在相同 ISA 和程序下反映实际性能 |
| 布线后工作频率、WNS | 说明单周期与流水线关键路径不同 |
| 数据/取指/访存停顿、冲刷 | 解释周期差异来源 |
| 预测准确率、Cache hit/miss | 解释附加功能收益 |
| LUT、寄存器、BRAM | 展示性能对应的资源代价 |
| 胜出所需频率比 | 判断更高频率能否抵消流水填充和停顿 |

答辩时不要说“流水线在所有情况下更快”。应使用经过验证的连续计算实验：

| 指标 | 大三单周期 CPU | 当前五级流水 CPU |
|---|---:|---:|
| 相同程序退休指令 | 194 | 194 |
| 周期数 | 194 | 198 |
| CPI | 1.0000 | 1.0206 |
| 通过布线后时序的工作频率 | 83.33 MHz | 90.91 MHz |
| CPU 时间 | 2.328 μs | 2.178 μs |
| MIPS | 83.33 | 89.07 |

流水线因填充多 4 个周期，但工作频率比达到 1.0909，高于胜出所需的 1.0206，最终 CPU 时间缩短 6.44%，MIPS 提高 6.89%。原始 5 元素排序在同频周期数上仍是单周期更少，说明分支、load-use 和冷启动会影响流水线收益。这种有限定条件的结论比选择性隐藏反例更可信。

### 4.4 下板内容

计组最终下板重点是证明“CPU 能在真实 FPGA 上可靠执行程序”，LCD 协议细节留给汇编课程。

- 实板由 JTAG 识别为 XC7A100T，CPU 使用 MMCM 产生的 25 MHz 时钟。
- IMEM/DMEM 使用片内 BRAM；基础 bring-up 配置关闭 Cache 和预测器以缩小故障范围。
- CPU 运行 `bringup.mem`，完成 ALU、相关、DMEM 和分支自检。
- UART 输出 `BOOT`、`PASS`；LED 显示阶段和 `TOHOST`；LCD 显示测试图案。
- 已记录参考实现 WNS、WHS、DRC、Route Status 和 BRAM 资源结果。
- 最终应用可演示俄罗斯方块，但计组只强调 CPU 正在运行汇编程序并通过 MMIO 控制外设。

## 5. 汇编与接口课程方案

### 5.1 推荐题目

**基于 ST7571 的可复用 LCD SPI 接口控制器及 RISC-V 汇编图形应用设计**

该题目与现有成果完全一致，工作量和展示效果都高于仅控制 LED 或只发送一个 UART 字符。它同时覆盖外设协议、硬件状态机、总线握手、MMIO、汇编驱动、图形应用和 FPGA 实测。

### 5.2 系统结构

```text
手柄/拨码 ----> GPIO MMIO -------------------------+
                                                    |
RISC-V 汇编程序 -> LW/SW -> 地址译码 -> LCD MMIO   |
                                  |                 |
                                  v                 v
                           LCD 控制器 IP <---- 10×20 棋盘数据
                                  |
                         SPI: CS/SCK/MOSI/RS/RST
                                  |
                                  v
                           ST7571 128×128 LCD

消行事件 -> BUZZER_TRIGGER MMIO -> 2 kHz/120 ms 蜂鸣器
调试文本 -> UART_TXDATA MMIO -> USB-UART
```

### 5.3 LCD 控制器硬件职责

- 完成 LCD 硬复位和上电等待。
- 发送 ST7571 初始化命令序列并清屏。
- 使用 4 线 SPI，MSB first，空闲低、上升沿采样。
- 通过 `tx_valid/tx_ready` 接收命令或数据，忙时拉低 ready。
- 保证一次 MMIO 请求只产生一次外设副作用。
- 保存 20 行、每行 10 位的棋盘缓冲。
- 把两行逻辑棋盘映射为一个 8 像素页面，每个方块使用 8 列实体和 2 列间隔。
- 支持固定文字、自清屏、重新初始化和整棋盘刷新。

### 5.4 MMIO 软件接口

| 地址 | 寄存器 | 软件用途 |
|---|---|---|
| `0x2000_0020` | `LCD_CMD` | 写低 8 位 LCD 命令 |
| `0x2000_0024` | `LCD_DATA` | 写低 8 位显示数据 |
| `0x2000_0028` | `LCD_STATUS` | bit0 ready，bit1 initialized |
| `0x2000_002C` | `LCD_CTRL` | 重新初始化、清屏、固定文字演示 |
| `0x2000_0030` | `LCD_GAME_ROW` | 写行号和 10 位棋盘数据 |
| `0x2000_0034` | `LCD_GAME_REFRESH` | 请求刷新完整棋盘 |
| `0x2000_0038` | `BUZZER_TRIGGER` | 消行后触发短音 |

所有 MMIO 地址均属于不可缓存、强顺序区域。LCD 忙时总线保持未完成，CPU 的存储等待机制保证汇编程序不会覆盖尚未发送的数据。

### 5.5 汇编软件分层

建议在报告中把 `firmware/tetris.S` 按以下层次说明，而不是逐行讲代码。

1. **底层驱动**
   - `lcd_wait_init`：轮询 `LCD_STATUS.initialized`。
   - `lcd_wait_ready`：等待发送端可接受新字节。
   - `lcd_write_cmd`、`lcd_write_data`：完成命令/数据 MMIO 写。
   - `lcd_clear`、`lcd_write_row`、`lcd_refresh`：封装常用显示操作。

2. **输入与定时**
   - 轮询 GPIO 中的左、右、上、下和开始开关。
   - 使用边沿检测避免一次按键被重复解释为多次移动。
   - 下键允许按住连续加速；普通下降使用软件计数延时。

3. **游戏数据结构**
   - DMEM 保存 20 个 10 位棋盘行。
   - 7 种方块、每种 4 个旋转状态以位图保存。
   - 当前方块用类型、旋转、x、y 坐标描述。

4. **核心算法**
   - 碰撞检测：边界检查与棋盘位图按位相与。
   - 移动和旋转：尝试新状态，碰撞则撤销。
   - 锁定：将活动方块按位或到固定棋盘。
   - 消行：检测 `0x3FF` 满行，上方各行下移并清顶行。
   - 刷新：合成活动方块和固定棋盘，逐行写入 LCD 缓冲后触发刷新。
   - 游戏结束与重开：生成位置碰撞时显示状态，等待 SW0 重新开始。
   - 音效：发生消行时写 `BUZZER_TRIGGER`，CPU 不等待音调播放结束。

### 5.6 汇编课程验证方案

| 层次 | 测试对象 | 通过标准 |
|---|---|---|
| SPI 单元测试 | `lcd_spi_master` | 每个字节位序、SCK、CS、RS 和 ready 时序正确 |
| 控制器单元测试 | `lcd_controller` | 复位、初始化、清屏、固定文字、棋盘刷新通过 |
| MMIO 系统测试 | CPU + 地址译码 + LCD | 读状态、写命令/数据、等待期间不重复写 |
| 游戏系统测试 | `tetris.mem` | 左右移动、旋转、软降、碰撞、锁定、消行和蜂鸣器事件正确 |
| IP 复用测试 | IP Catalog/Block Design | 能注册、例化、Validate、生成输出产品 |
| 实板测试 | EES-338 + LCD + 手柄 | 初始化正常、画面方向正确、控制响应正常、消行有声音 |
