# EES-338 下板方案

## 1. 结论

当前 CPU 工程已经完成 EES-338 移植，可以生成并下载 bitstream。实现使用
`ees338_top` 作为板级顶层；`soc_top` 继续只承担 SoC 逻辑。精确约束、同步 BRAM、
启动程序、物理 UART 和 LCD 控制器均已接入。

EES-338 与当前 Vivado 工程的目标器件匹配：

- 开发板 FPGA：Xilinx Artix-7 `XC7A35T-1CSG324C`；
- 工程器件：`xc7a35tcsg324-1`；
- 板载系统时钟：100 MHz，FPGA 管脚 `T5`；
- 逻辑复位：`P15`，原理图中上拉、按键接地，因此按下为低电平；
- 所有本方案使用的普通 I/O 均采用 `LVCMOS33`。

仿真、综合、实现脚本以及图形界面工程已统一为 `xc7a35tcsg324-1`。

上述型号对应随仓库提供的标准版说明书。若 Hardware Manager 实际识别为
`xc7a100t_0`，说明所连接实板是 100T 版本；应将工程器件改为
`xc7a100tcsg324-1` 并重新生成 bitstream。JTAG 识别到的芯片型号优先于文档型号，
35T 与 100T 的 bitstream 不能混用。

## 2. 首版下板目标

首版只验证最短闭环，不一次接入全部高级功能：

1. 25 MHz CPU 时钟；
2. 低有效按键复位；
3. 8 个拨码开关输入、8 个 LED 输出；
4. 板载 USB-UART 输出；
5. 板载 LCD 通过 4 线 SPI 显示自检结果；
6. IMEM 和 DMEM 使用 FPGA 内部 BRAM；
7. 首次下板关闭 I-Cache、D-Cache 和动态分支预测，基础程序通过后逐项开启。

首版不使用板载异步 SRAM、VGA、以太网、蓝牙、蜂鸣器和数码管。这些外设保持未驱动或安全静态状态。

## 3. 板级结构

```text

    v

    |
    +-- ees338_top --------------------------------------+
        |                                                |
        +-- soc_top                                      |
        |    +-- cpu_core                                |
        |    +-- I/D Cache                               |
        |    +-- BRAM IMEM/DMEM                          |
        |    +-- GPIO/MMIO                               |

```

`soc_top` 保持为 SoC 逻辑顶层；`ees338_top` 是综合、实现和生成 bitstream 使用的唯一板级顶层。

## 4. 板级顶层接口

推荐端口定义：

```systemverilog
module ees338_top (
  input  logic       sys_clk,
  input  logic       reset_n,
  input  logic [7:0] sw,
  input  logic [4:0] key,
  output logic [7:0] led,
  input  logic       uart_rxd,
  output logic       uart_txd,
  output logic       lcd_wr,
  output logic       lcd_rd,
  output logic [7:0] lcd_d,
  output logic       lcd_cs_n,
  output logic       lcd_rst_n,
  output logic       lcd_rs
);
```

建议连接关系：

- `gpio_in = {19'b0, key[4:0], sw[7:0]}`；
- 正常模式下 `led = gpio_out[7:0]`；
- `sw[7]=1` 时切换到调试显示，例如 LED 显示复位、LCD 初始化、UART 忙、`tohost` PASS/FAIL；
- `key[0]` 经双触发器同步后连接 `ext_irq`；
- `uart_tx_ready/valid/data` 接物理 UART 发送器的握手接口；
- 性能计数器不导出到 FPGA 管脚，使用 ILA 或后续 MMIO 读取。

## 5. 时钟与复位

### 5.1 时钟

板载时钟是 100 MHz。第一版建议使用 MMCM/Clock Wizard 产生 25 MHz CPU 时钟，而不是用普通逻辑直接分频后作为时钟。

选择 25 MHz 的原因：

- 为五级流水 CPU、Cache 和新增外设留出较大时序余量；
- 25 MHz 可以方便地产生 115200 baud UART；
- LCD SPI 只需约 2 MHz，不需要高速系统时钟。

基础时钟约束：

```tcl
set_property PACKAGE_PIN T5 [get_ports sys_clk]
set_property IOSTANDARD LVCMOS33 [get_ports sys_clk]
create_clock -period 10.000 -name sys_clk -waveform {0.000 5.000} [get_ports sys_clk]
```

### 5.2 复位

P15 在板上被 4.7 kOhm 上拉，按键按下接地，因此是低有效复位。板级逻辑应采用“异步置位、同步释放”：

```systemverilog
logic [1:0] reset_pipe;

always_ff @(posedge cpu_clk or negedge reset_n) begin
  if (!reset_n)
    reset_pipe <= 2'b11;
  else
    reset_pipe <= {reset_pipe[0], 1'b0};
end

assign soc_reset = reset_pipe[1] | ~clk_locked;
```

约束：

```tcl
set_property PACKAGE_PIN P15 [get_ports reset_n]
set_property IOSTANDARD LVCMOS33 [get_ports reset_n]
```

### 6.2 通用按键

## 7. USB-UART 方案

板载 CP2102 与 FPGA 的正确连接为：

| FPGA 功能 | 原理图网络 | FPGA 管脚 |
|---|---|---|
| 发送 TX | `UART_RX`（CP2102 接收端） | T4 |
| 接收 RX | `UART_TX`（CP2102 发送端） | N5 |

随板 `BitExample.rar` 中“USB-RS232”注释下面的 N2/L3 实际是蓝牙 UART 管脚，不能复制为 USB-UART 约束；USB-UART 应以用户手册和原理图的 T4/N5 为准。

首版只实现发送，参数为 115200 baud、8 数据位、无校验、1 停止位。25 MHz 下可使用 217 个时钟周期/bit，误差很小。

```tcl
set_property PACKAGE_PIN T4 [get_ports uart_txd]
set_property IOSTANDARD LVCMOS33 [get_ports uart_txd]
set_property PACKAGE_PIN N5 [get_ports uart_rxd]
set_property IOSTANDARD LVCMOS33 [get_ports uart_rxd]
```

CPU 已有的 `uart_tx_valid/uart_tx_data/uart_tx_ready` 可直接连接物理发送器：忙时 `ready=0`，发送器接受一个字节后拉低 `ready`，完成停止位后恢复。

## 8. 板载 LCD 方案

板载 LCD 是 JLX128128G/JLX128218G-81202 系列模块，控制器为 ST7571。原理图已经把 LCD 的 VDD 和背光接到板载电源，FPGA 不需要也不应驱动 LCD 电源。

### 8.1 接口选择

采用 4 线 SPI：

- `LCD_D7` 作为串行数据 SDA；
- `LCD_D6` 作为串行时钟 SCK；
- `LCD_RS` 区分命令和数据；
- `LCD_CS` 为低有效片选；
- `LCD_RST` 为低有效复位；
- `LCD_D[5:0]`、`LCD_RD` 和 `LCD_WR` 在串行模式下保持高电平。

推荐 SPI 时钟 2 MHz、MSB first、空闲低、上升沿采样。该频率满足 LCD 手册中周期至少 200 ns、高低电平至少 80 ns 的要求。

### 8.2 LCD 管脚

| 端口 | LCD 功能 | FPGA 管脚 | 串行模式处理 |
|---|---|---|---|
| `lcd_wr` | WR | V9 | 保持 1 |
| `lcd_rd` | RD | U7 | 保持 1 |
| `lcd_d[0]` | D0 | T1 | 保持 1 |
| `lcd_d[1]` | D1 | M6 | 保持 1 |
| `lcd_d[2]` | D2 | N6 | 保持 1 |
| `lcd_d[3]` | D3 | R6 | 保持 1 |
| `lcd_d[4]` | D4 | R5 | 保持 1 |
| `lcd_d[5]` | D5 | V7 | 保持 1 |
| `lcd_d[6]` | D6/SCK | V6 | SPI 时钟 |
| `lcd_d[7]` | D7/SDA | U9 | SPI 数据 |
| `lcd_cs_n` | CS | U6 | 低有效片选 |
| `lcd_rst_n` | RST | R7 | 低有效复位 |
| `lcd_rs` | A0/RS | T6 | 0=命令，1=数据 |

所有 LCD 信号约束为 `LVCMOS33`。建议为 SCK/SDA/CS 设置较低驱动和慢摆率以减小边沿噪声：

```tcl
set_property DRIVE 8 [get_ports {lcd_d[6] lcd_d[7] lcd_cs_n lcd_rst_n lcd_rs}]
set_property SLEW SLOW [get_ports {lcd_d[6] lcd_d[7] lcd_cs_n lcd_rst_n lcd_rs}]
```

### 8.3 上电初始化

LCD 控制器硬件状态机负责：

1. FPGA 时钟稳定后保持 `lcd_rst_n=0`；
2. 复位低电平保持至少 2 us；建议实际保持 1 ms；
3. 拉高复位后等待到上电累计至少 120 ms；
4. 按 LCD 手册发送 ST7571 初始化命令序列；
5. 清屏并设置 `initialized=1`；
6. 此后接受 CPU 的命令/数据写请求。

### 8.4 LCD MMIO

在现有 GPIO/UART 地址之后增加：

| 地址 | 名称 | 访问 | 功能 |
|---|---|---|---|
| `0x2000_0020` | `LCD_CMD` | WO | 写低 8 位发送命令 |
| `0x2000_0024` | `LCD_DATA` | WO | 写低 8 位发送显示数据 |
| `0x2000_0028` | `LCD_STATUS` | RO | bit0=`ready`，bit1=`initialized` |
| `0x2000_002C` | `LCD_CTRL` | WO | bit0=重新初始化，bit1=清屏 |

当 SPI 发送器忙时，`LCD_CMD` 和 `LCD_DATA` 写操作必须保持 `bus_ready=0`，利用现有流水线存储等待机制阻止同一写操作重复产生副作用。

首版不需要完整帧缓冲，只提供命令/数据 FIFO。演示程序可以显示十六进制数值，避免引入除法和复杂字库。

## 9. 存储器方案

### 9.1 首版：内部 BRAM

当前 IMEM/DMEM 使用组合读数组，不能可靠推断 Xilinx Block RAM。需要改成同步读、下一周期返回 `ready` 的结构。

建议初始容量：

- IMEM：2048 x 32 bit = 8 KiB；
- DMEM：2048 x 32 bit = 8 KiB；
- 程序由 `bringup.mem` 通过 `$readmemh` 初始化；
- 未使用地址返回 0 或 NOP，并设置调试错误标志。

16 KiB 的基础配置只占少量 XC7A35T BRAM。完成 BRAM 改造后，应同时在 Cache 开启和关闭两种配置下重跑系统测试，因为存储器响应将从组合响应变为至少一个周期响应。

### 9.2 第二版：板载异步 SRAM

EES-338 提供 16 位数据总线和 19 位地址总线的异步 SRAM。CPU 是 32 位，因此一个 32 位访问至少需要两个 16 位 SRAM 周期，还需要：

- I/D 请求仲裁；
- 32 位到两个 16 位半字的拆分/合并；
- `LB/UB` 字节使能；
- 读写时序状态机；
- 数据总线三态控制；
- Cache refill 与写直达处理。

因此 SRAM 不放入第一次下板范围。BRAM 版本稳定后，可把 SRAM 映射到新的大容量地址窗口，用于性能或容量扩展。

## 11. 启动程序与可观察结果

`bringup.mem` 建议执行以下自检：

1. 设置栈指针；
2. 写 `GPIO_OUT=0x01`，确认 CPU 已开始执行；
3. 进行 ALU、寄存器、load/store、branch、JAL/JALR 自检；
4. 通过 USB-UART 输出 `BOOT` 和每一阶段结果；
5. 等待 `LCD_STATUS.initialized=1`；
6. LCD 显示 `CPU OK`、周期数、分支错误数和 Cache hit/miss；
7. 成功时写 `TOHOST=1` 并令绿色 LED 常亮；
8. 失败时写非 1 错误码，并让黄色 LED 按错误码闪烁。

首版建议的 LED 定义：

| LED | 含义 |
|---|---|
| LED0 | CPU 已脱离复位 |
| LED1 | BRAM 自检通过 |
| LED2 | UART 已发送启动信息 |
| LED3 | LCD 初始化完成 |
| LED4 | CPU 指令自检失败 |
| LED5 | 存储器自检失败 |
| LED6 | LCD/UART 超时 |
| LED7 | `TOHOST` PASS |

## 12. 实施阶段和验收门槛

### 阶段 A：板级最小工程

- `ees338_top` 只做 25 MHz 心跳 LED、复位和拨码回显；
- 验收：Vivado 实现通过，时序裕量大于 0，所有管脚均已约束；
- 下板：LED 流水和按键复位现象正确。

### 阶段 B：CPU + BRAM + UART

- 使用内部 BRAM，关闭两个 Cache 和预测器；
- 验收：同步 BRAM 仿真通过，综合报告出现预期 RAMB18/RAMB36；
- 下板：UART 输出 `BOOT/PASS`，LED 显示 `TOHOST=1`。

### 阶段 C：LCD

- 先用与 CPU 无关的硬件状态机显示全屏、棋盘格和固定字符；
- 再接入 LCD MMIO；
- 验收：复位、初始化、清屏和连续写数据均无超时，CPU 忙等待期间不会重复写 LCD。

### 阶段 D：高级功能

- 依次启用分支预测、I-Cache、D-Cache；
- 每开启一项都要求程序最终结果和 `TOHOST` 不变；
- 记录周期数、命中率和误预测率，用 LCD/UART/ILA 观察。

### 阶段 E：最终实现

必须同时满足：

- 器件与实板一致：标准版为 `xc7a35tcsg324-1`，100T 版为
  `xc7a100tcsg324-1`；
- `report_io` 无未约束端口；
- `report_drc` 无 Error；
- `report_timing_summary` 的 WNS/TNS 均不为负；
- BRAM 推断数量符合配置；
- I/O 数量小于封装可用数量；
- 六个现有回归测试和新增板级/LCD/UART 测试全部通过；
- JTAG 下载后 LED、UART 和 LCD 三条观察通道结果一致。

## 13. 风险与处理

| 风险 | 处理 |
|---|---|
| `.xpr` 与 Tcl 脚本器件封装不一致 | 全部统一为 `xc7a35tcsg324-1` |
| 现有顶层导出数百个调试位 | 由 `ees338_top` 隐藏，改用 ILA/MMIO |
| 组合读存储器不推断 BRAM | 改为同步读并重测 Cache/stall |
| 100 MHz 时序压力 | 首版 CPU 使用 25 MHz MMCM 输出 |
| UART 示例约束误指向蓝牙 | USB-UART 固定使用 T4/N5 |
| LCD 上电后无显示 | 严格执行复位和 120 ms 等待，先做硬件固定图案测试 |
| LCD 串行写被重复执行 | 忙时拉低总线 `ready`，完成后只产生一次响应 |
| 一次加入全部高级功能难以定位 | Cache、预测和 LCD 分阶段启用 |

## 14. 推荐最终演示

1. 上电后 LED0 点亮，UART 输出 `BOOT`；
2. LCD 显示课程设计名称和 `CPU SELF TEST`；
3. CPU 完成自检后显示 `PASS`；
4. 拨码开关选择显示页面：寄存器值、周期数、Cache 命中率、分支预测统计；
5. 按键产生外部中断，LCD 中断计数和 LED 同步变化；
6. 通过 UART 保存完整的测试结果，作为答辩和报告证据。
