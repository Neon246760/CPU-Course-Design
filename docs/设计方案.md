# 基于微程序控制器的流水线 CPU 设计方案

## 1. 项目概述

### 1.1 项目名称

基于微程序控制器、支持溢出判断、中断、Cache 与分支预测的五级流水线计算机系统设计与实现。

### 1.2 总体目标

使用 HDL（建议 SystemVerilog，也可根据课程要求使用 Verilog）设计一套可综合、可仿真、可下板验证的 32 位流水线 CPU。CPU 采用微程序控制器生成主要控制信号，具备完整的运算类、传送类和控制类指令，并实现流水线相关处理、算术溢出判断、精确中断/异常、一级 Cache 和动态分支预测。

最终系统至少应做到：

- 支持不少于 16 条指令；
- 能连续执行完整的汇编测试程序；
- 正确处理数据相关、结构相关和控制相关；
- 能检测有符号加减法溢出；
- 能响应外部中断并执行中断服务程序；
- 能通过 Cache 加速取指或数据访问；
- 能通过分支预测减少控制相关造成的流水线停顿；
- 能统计周期数、指令数、停顿数、预测次数、误预测次数和 Cache 命中/缺失次数；
- 能与组内成员大三阶段完成的单周期 CPU 进行量化性能对比；
- 通过模块级仿真、系统级仿真，并争取完成 FPGA 下板。

### 1.3 设计原则

1. **先完成基础流水线，再逐项增加附加功能。**附加功能不得阻塞基础 CPU 的验证。
2. **各模块接口先行。**编码前冻结指令格式、流水级接口、存储器接口、异常接口和统计接口。
3. **所有功能均有定向测试。**不能只依靠一个综合程序证明正确性。
4. **保持精确体系结构状态。**发生异常、中断或分支误预测时，错误路径指令不得修改寄存器或存储器。
5. **功能可参数化关闭。**建议为 Cache、分支预测和中断设置参数或编译开关，便于定位故障和开展性能对比。

## 2. 总体架构

### 2.1 推荐技术路线

- 数据宽度：32 位；
- 指令宽度：32 位；
- 地址宽度：32 位；
- 通用寄存器：32 个，每个 32 位，其中 `x0` 恒为 0；
- 指令集：RV32I 教学子集，不少于 16 条；
- 流水级数：经典五级流水线；
- 控制方式：微程序控制器与流水线分布式控制相结合；
- 存储体系：Harvard 结构接口，指令通路和数据通路分离；
- Cache：优先实现一级直接映射指令 Cache，再根据进度实现数据 Cache；
- 分支预测：BTB + 2 位饱和计数器 BHT；
- 中断：单一外部可屏蔽中断起步，扩展为定时器/外部中断；
- 开发方式：模块级单元测试 → CPU 系统仿真 → 综合与时序检查 → FPGA 下板。

采用 RV32I 子集的原因是指令编码规则清晰、寄存器数量充足、便于编写汇编测试程序；本项目只独立实现所选子集，不复制网络处理器代码。

### 2.2 五级流水线

| 流水级 | 名称 | 主要工作 |
|---|---|---|
| IF | 取指 | 选择下一 PC，经 I-Cache 取指，进行分支预测 |
| ID | 译码 | 解析指令、读取寄存器、查询微程序控制存储器、产生控制字 |
| EX | 执行 | ALU 运算、比较、地址计算、分支实际结果判断、溢出检测 |
| MEM | 访存 | 访问 D-Cache/数据存储器，处理访存等待与存储提交 |
| WB | 写回 | 将 ALU 或访存结果写回通用寄存器，并统计退休指令 |

级间设置 `IF/ID`、`ID/EX`、`EX/MEM`、`MEM/WB` 四组流水寄存器。每组流水寄存器至少包含：

- 当前指令和 PC；
- 操作数及立即数；
- 源/目的寄存器编号；
- 该指令需要的控制字段；
- 有效位 `valid`；
- 分支预测信息；
- 异常信息；
- 必要的计算结果和存储数据。

`valid` 位用于表示该级是否含有有效指令。暂停时保持有关流水寄存器，冲刷时清除相应 `valid`，从而避免气泡或错误路径指令产生副作用。

### 2.3 顶层数据流

```text
                         +----------------------+
                         | 微程序控制存储器     |
                         | opcode/funct -> 控制字|
                         +----------+-----------+
                                    |
PC -> 分支预测器 -> I-Cache -> IF/ID -> ID/EX -> EX/MEM -> MEM/WB
       ^                  译码/寄存器   ALU/分支   D-Cache    写回
       |                               |
       +------- 预测更新/重定向 --------+

外部中断 -> CSR/中断控制器 -> 流水线仲裁与冲刷 -> 中断入口 PC
Cache miss、数据冒险、异常、误预测 -> 流水线控制器
```

## 3. 指令系统设计

### 3.1 基础指令集合

建议实现以下 25 条左右的 RV32I 指令，超过“不少于 16 条”的要求，并覆盖三类指令：

| 类别 | 指令 | 功能 |
|---|---|---|
| 算术运算 | `ADD`、`SUB`、`ADDI` | 加、减、立即数加 |
| 逻辑运算 | `AND`、`OR`、`XOR`、`ANDI`、`ORI`、`XORI` | 位逻辑运算 |
| 移位运算 | `SLL`、`SRL`、`SRA` | 逻辑/算术移位 |
| 比较运算 | `SLT`、`SLTU` | 有符号/无符号比较 |
| 传送访存 | `LW`、`SW`、`LB`、`LBU`、`SB` | 字/字节加载和存储 |
| 条件分支 | `BEQ`、`BNE`、`BLT`、`BGE` | 条件控制转移 |
| 无条件跳转 | `JAL`、`JALR` | 跳转并保存返回地址 |
| 高位立即数 | `LUI`、`AUIPC` | 构造常数和 PC 相对地址 |
| 系统控制 | `ECALL`、`MRET` | 软件异常与中断返回 |

如希望严格体现“算术溢出触发异常”，可以在标准 RV32I 之外增加自定义 `ADDV/SUBV`，或者规定课程设计中的 `ADD/SUB/ADDI` 在有符号溢出时产生异常。必须在报告中明确这一点，因为标准 RV32I 的整数加减本身不触发溢出异常。

### 3.2 必须完成的指令集文档

编码前建立指令规格表，每条指令均填写：

- 指令名称、类型和 32 位编码；
- `opcode`、`funct3`、`funct7`；
- 源寄存器和目的寄存器；
- 立即数生成规则；
- ALU 操作；
- 是否读/写存储器；
- 是否写通用寄存器；
- 是否为分支或跳转；
- 是否可能产生溢出或其他异常；
- 对应微地址和控制字。

## 4. 微程序控制器设计

### 4.1 微程序控制器在流水线中的定位

传统多周期 CPU 会让一条指令依次执行多条微指令，但若直接照搬到五级流水线，会阻碍多条指令并行。为兼顾“微程序控制器”和流水线，本设计采用以下方式：

1. 在 ID 级根据 `opcode/funct` 形成微程序入口地址；
2. 查询控制存储器，读出该指令的微控制字；
3. 将微控制字按 EX、MEM、WB 阶段拆分；
4. 控制字段随该指令经过流水寄存器向后传递；
5. 冒险、暂停、冲刷、Cache 等待和中断优先级由独立的流水线仲裁器控制。

因此，**微程序控制器负责“这条指令要做什么”，流水线仲裁器负责“这条指令何时前进、暂停或作废”**。这种结构既保留了微程序控制的可修改性，又适合流水执行。

对于普通指令，每条指令可以对应一条水平型微指令。对于 `MRET`、异常入口或复杂扩展指令，可以使用微程序入口地址和微地址顺序/转移逻辑执行多条微指令；执行多微指令期间应暂停前端或把该操作交由独立状态机完成。

### 4.2 控制存储器

建议使用 ROM 或 FPGA Block RAM 实现控制存储器：

- 深度：64 或 128 项；
- 宽度：按最终控制字段确定，预计 32～48 位；
- 读地址：由译码映射表或微地址寄存器 `uPC` 产生；
- 输出：当前微控制字；
- 初始化：使用 `case`、ROM 初始化文件或综合工具支持的存储器初始化格式。

### 4.3 微控制字建议字段

| 字段 | 作用 |
|---|---|
| `alu_op` | ALU 运算类型 |
| `op_a_sel` | ALU 操作数 A 选择：`rs1/PC/0` |
| `op_b_sel` | ALU 操作数 B 选择：`rs2/imm/4` |
| `imm_type` | I/S/B/U/J 型立即数选择 |
| `reg_write` | 是否写通用寄存器 |
| `wb_sel` | 写回数据选择：ALU/访存/PC+4/CSR |
| `mem_read` | 是否读取数据存储器 |
| `mem_write` | 是否写数据存储器 |
| `mem_size` | 字节、半字或字访问 |
| `load_unsigned` | 加载时零扩展或符号扩展 |
| `branch_type` | 分支比较条件 |
| `jump` | 是否为无条件跳转 |
| `overflow_check` | 是否检查有符号溢出 |
| `csr_op` | CSR 读取、写入或无操作 |
| `exception_op` | ECALL、MRET 或其他系统操作 |
| `next_mode` | 微地址顺序、跳转、条件转移或结束 |
| `next_uaddr` | 下一微地址/分支目标微地址 |

微控制字在进入 `ID/EX` 后，应只保留后续阶段需要的字段，避免无关控制信号在整个数据通路中扩散。

### 4.4 微程序开发任务

- 设计指令译码到微地址的映射；
- 定义微控制字格式；
- 编写所有基础指令的微程序；
- 编写异常入口、`MRET` 等系统微程序；
- 编写非法指令的默认微程序；
- 输出微程序地址和控制字作为调试信号；
- 编写脚本或人工核对表，检查每条指令的控制字段是否完整且互斥；
- 仿真验证不同指令译码得到的控制字。

## 5. 基础数据通路模块

### 5.1 PC 与取指单元

需要实现：

- PC 寄存器和复位入口地址；
- `PC+4` 计算；
- 顺序地址、预测目标、分支纠正目标、异常入口地址和 `mepc` 的多路选择；
- I-Cache 请求/响应握手；
- Cache miss 时保持 PC 和 IF/ID；
- 取指地址对齐检查；
- 为每条取出的指令附带预测信息。

### 5.2 寄存器堆

- 32 个 32 位通用寄存器；
- 两个组合读端口、一个同步写端口；
- `x0` 固定为 0；
- 同周期写后读旁路，或在前递网络中解决；
- 仿真时提供寄存器观察接口。

### 5.3 立即数生成器

支持 I、S、B、U、J 型立即数，并完成正确的符号扩展和位拼接。每种类型需要独立定向测试。

### 5.4 ALU 和比较器

ALU 至少支持：

- 加、减；
- 与、或、异或；
- 逻辑左移、逻辑右移、算术右移；
- 有符号和无符号小于比较；
- 地址计算；
- 相等、不等及大小关系判断；
- 加减法有符号溢出输出。

### 5.5 加载/存储单元

- 生成字节写使能；
- 完成加载数据的字节选择与符号/零扩展；
- 对未对齐地址进行异常检测，或明确只支持自然对齐访问；
- 将外设地址范围与普通存储器地址范围区分；
- 保证被冲刷的存储指令不会真正写存储器。

## 6. 流水线相关与仲裁设计

### 6.1 数据相关

实现前递单元，将数据从以下位置前递到 EX 级：

- `EX/MEM` 的 ALU 结果 → 当前指令的 `rs1/rs2`；
- `MEM/WB` 的写回结果 → 当前指令的 `rs1/rs2`；
- 必要时将写回结果前递到 ID 级分支比较或寄存器读取；
- 将最新的 `rs2` 数据前递给存储指令写数据端。

前递选择必须排除 `rd=x0` 和 `reg_write=0` 的情况，并明确 `EX/MEM` 相比 `MEM/WB` 具有更高优先级。

### 6.2 Load-use 冒险

加载指令的数据通常到 MEM 级末尾才可用。若其后一条指令立即使用该结果，需要：

- 保持 PC；
- 保持 IF/ID；
- 向 ID/EX 插入气泡；
- 下一周期由 MEM/WB 前递加载结果。

如果 D-Cache 缺失，则不能只暂停一个周期，应保持相关后端状态直至数据返回。

### 6.3 结构相关

- 采用独立 I-Cache 与 D-Cache 接口，避免取指和数据访问直接争用端口；
- 若两级 Cache 共用单端口主存，应在下层实现总线仲裁器；
- 建议 D-Cache miss 优先于 I-Cache miss，以便旧指令尽快完成；
- 微程序控制存储器应具有独立读端口，不与普通存储器冲突。

### 6.4 控制相关

- IF 级根据预测器选择下一 PC；
- EX 级得到分支实际方向和实际目标；
- 预测正确则流水线继续；
- 预测错误则清除 IF/ID 和 ID/EX，将 PC 重定向到正确地址；
- `JAL/JALR` 的目标处理和返回地址写回应分别验证；
- 错误路径上的存储、寄存器写和预测器之外的体系结构副作用必须被禁止。

### 6.5 全局流水线控制优先级

必须使用统一仲裁器，避免多个模块同时控制 PC 和流水寄存器。建议从高到低采用：

1. 复位；
2. 已确认的同步异常；
3. 可接受的外部中断；
4. 分支误预测/跳转重定向；
5. D-Cache miss 或数据存储器等待；
6. I-Cache miss；
7. load-use 暂停；
8. 正常推进。

中断只能在安全的指令边界接受；若更老的指令仍可能产生异常或存储副作用，应先完成或取消这些指令。最终实现中要为各级分别生成 `stall`、`flush` 和 `enable`，不能只用一个全局暂停信号粗略处理所有情况。

## 7. 溢出判断设计

### 7.1 检测规则

32 位有符号加法 `result = a + b`：

```text
overflow_add = (~(a[31] ^ b[31])) & (result[31] ^ a[31])
```

32 位有符号减法 `result = a - b`：

```text
overflow_sub = (a[31] ^ b[31]) & (result[31] ^ a[31])
```

无符号运算的进位/借位与有符号溢出是不同概念，应分别命名，不能混用。

### 7.2 流水线处理

- 在 EX 级产生溢出标志；
- 只有微控制字中的 `overflow_check=1` 时才形成异常；
- 将发生异常指令的 PC 写入 `mepc`；
- 将异常原因写入 `mcause`；
- 禁止该指令及其后继错误指令修改寄存器或存储器；
- 清除更年轻的流水线指令；
- PC 跳转到 `mtvec` 指定的异常入口；
- 中断/异常服务程序通过 `MRET` 返回。

### 7.3 测试内容

- 最大正数加 1；
- 最小负数减 1；
- 正数减负数导致溢出；
- 负数减正数导致溢出；
- 普通加减不误报；
- 逻辑运算和无符号比较不误触发；
- 溢出指令位于分支错误路径时不得触发体系结构异常。

## 8. 中断与异常系统设计

### 8.1 最小可行中断系统

第一版实现一个外部可屏蔽中断输入 `ext_irq`，包含以下状态：

| CSR/寄存器 | 作用 |
|---|---|
| `mstatus.MIE` | 全局中断允许位 |
| `mie` | 各中断源允许位 |
| `mip` | 中断挂起状态 |
| `mtvec` | 异常/中断入口地址 |
| `mepc` | 返回地址 |
| `mcause` | 中断或异常原因 |

如时间允许，可增加周期计数器产生的定时器中断。

### 8.2 中断进入过程

1. 对外部异步中断输入进行双触发器同步；
2. 将中断请求锁存为 pending，防止窄脉冲丢失；
3. 检查全局和分项中断使能；
4. 等待安全的指令退休边界；
5. 将恢复执行所需 PC 保存到 `mepc`；
6. 设置 `mcause`，保存并关闭全局中断使能；
7. 清除年轻指令，跳转至 `mtvec`；
8. 执行中断服务程序；
9. `MRET` 恢复中断状态，并从 `mepc` 返回。

需要在设计文档中明确定义：`mepc` 保存“被中断后下一条应执行的指令地址”，并用测试证明不会重复提交或跳过指令。

### 8.3 异常和中断优先级

建议优先级为：

1. 当前更老指令的同步异常；
2. 当前可接受的外部/定时器中断；
3. 分支误预测；
4. 普通流水线推进。

同步异常包括：非法指令、指令地址错误、加载/存储地址未对齐、溢出异常和 `ECALL`。如果工期紧张，至少实现非法指令、溢出和外部中断，并在报告中说明未实现项。

### 8.4 中断测试

- 在普通 ALU 指令之间触发中断；
- 在 load-use 暂停期间触发中断；
- 在 D-Cache miss 期间触发中断；
- 在分支预测错误附近触发中断；
- 中断屏蔽时保持 pending，重新使能后响应；
- 验证 `MRET` 返回地址和寄存器状态；
- 验证中断前的老指令已完成，中断后的年轻指令未错误提交。

## 9. Cache 设计

### 9.1 实施范围与分阶段策略

Cache 是本方案中工作量最大的附加功能之一，建议分两阶段：

- 第一阶段：实现只读 I-Cache，验证命中和缺失填充；
- 第二阶段：实现 D-Cache，并处理写策略、字节写和缺失；
- 若工期不足，至少保证 I-Cache 可用，并将 D-Cache 作为明确的扩展项；若对老师承诺“支持 Cache”，报告中应清楚说明实际支持的类型。

### 9.2 推荐参数

为降低实现风险，建议采用：

- 映射方式：直接映射；
- Cache line：16 字节（4 个 32 位字）；
- 容量：1 KiB 或 2 KiB；
- 替换方式：直接映射无需替换算法；
- I-Cache：只读、缺失时整行填充；
- D-Cache：优先写直达（write-through）+ 写不分配（no-write-allocate）；
- 有效位：每行 1 位；
- D-Cache 如采用写回策略，还需 dirty 位和回写状态机，风险明显更高。

以 1 KiB、16 B/line 的直接映射 Cache 为例：

- 行数：64；
- 块内偏移：4 位；
- 索引：6 位；
- 标记：32 - 4 - 6 = 22 位。

具体位宽必须由最终容量和地址空间重新计算并记录。

### 9.3 Cache 模块组成

- Tag RAM；
- Data RAM；
- Valid 数组；
- 地址拆分逻辑；
- 命中比较器；
- 缺失处理状态机；
- 下层存储器请求/响应接口；
- CPU 侧 `req/addr/write/wdata/wstrb/ready/rdata` 接口；
- 命中数、缺失数和访问数计数器；
- 复位或失效处理逻辑。

### 9.4 I-Cache 缺失状态机

建议状态：

1. `IDLE/LOOKUP`：查询 tag 和 valid；
2. `MISS_REQ`：向下层存储器发起行填充；
3. `REFILL`：接收一个或多个字并写入 data array；
4. `UPDATE`：更新 tag 和 valid；
5. `RESP`：将目标字返回 CPU，解除 IF 暂停。

必须保存发生 miss 时的请求地址，防止 PC 在等待期间变化造成回填错误。

### 9.5 D-Cache 与外设一致性

存储器映射 I/O 地址不得进入普通 Cache。地址译码应为外设区域产生 `uncached`，直接访问外设总线。否则对 UART 等带副作用寄存器进行缓存会导致读写行为错误。

建议：

- 普通 RAM 地址：可缓存；
- 外设地址：强制非缓存；
- 中断控制/计时器寄存器：强制非缓存；
- 写直达 D-Cache 等待下层写完成后再确认存储指令完成。

### 9.6 Cache 测试

- 冷启动第一次访问发生 miss；
- 同一行重复访问命中；
- 同一 Cache 行内不同字偏移读取正确；
- 相同 index、不同 tag 发生替换；
- Cache miss 期间流水线稳定；
- 分支误预测期间错误路径的 I-Cache 响应不会成为有效指令；
- 字节写使能正确；
- 外设地址绕过 Cache；
- 统计命中率，并对比启用/关闭 Cache 的周期数。

## 10. 分支预测设计

### 10.1 预测结构

建议实现小型 BTB 与 BHT：

- BTB：保存分支指令 PC tag、预测目标地址和有效位；
- BHT/PHT：每项一个 2 位饱和计数器；
- 初始状态：弱不跳转；
- IF 级：使用当前 PC 查询 BTB/BHT；
- 预测跳转条件：BTB 命中且计数器高位为 1；
- EX 级：计算实际方向和实际目标，判断是否误预测；
- 分支完成后更新 BTB 和计数器。

计数器状态：

```text
00 强不跳转
01 弱不跳转
10 弱跳转
11 强跳转
```

实际跳转时计数器加一并饱和，实际不跳转时减一并饱和。

### 10.2 流水线中携带的预测信息

每条控制转移指令至少携带：

- `pred_taken`；
- `pred_target`；
- 预测时的 PC；
- BHT/BTB 索引；
- BTB 是否命中。

EX 级利用这些信息判断：

- 方向是否预测错误；
- 目标地址是否预测错误；
- 正确下一 PC；
- 是否需要冲刷流水线；
- 是否更新预测表。

### 10.3 预测器更新约束

- 只在已确认是有效控制转移指令时更新；
- 被更老异常或中断取消的指令不应更新预测器；
- 同一条分支只能更新一次；
- `JAL` 可在 BTB 命中后直接预测跳转；
- `JALR` 的间接目标可先按不预测或使用 BTB 记录目标；
- 如不实现返回地址栈，应在报告中明确函数返回的预测能力有限。

### 10.4 预测测试

- 始终不跳转分支；
- 始终跳转循环；
- 连续多次跳转后退出的循环；
- 跳转/不跳转交替模式；
- 相同索引、不同 PC 的 BTB 冲突；
- 目标地址发生变化；
- 误预测后 PC 和流水线恢复正确；
- 对比静态不跳转和动态预测的误预测率、CPI 与总周期。

## 11. 存储器与外设接口

### 11.1 统一握手接口

CPU/Cache 与下层存储器建议采用简单握手协议：

```text
req       请求有效
addr      地址
write     读/写类型
wdata     写数据
wstrb     字节写使能
ready     请求完成
rdata     读数据
```

请求方在 `ready` 前保持请求信息稳定。这样可以自然支持单周期 RAM、慢速 RAM、Cache refill 和存储器映射外设。

### 11.2 地址空间规划

应在项目早期冻结地址表，例如：

| 地址范围 | 用途 | 是否缓存 |
|---|---|---|
| `0x0000_0000` 起 | 指令存储器 | I-Cache |
| `0x1000_0000` 起 | 数据 RAM | D-Cache |
| `0x2000_0000` 起 | UART/其他外设 | 否 |
| `0x2000_1000` 起 | 定时器/中断控制 | 否 |

具体地址可根据开发板 BRAM 和后续接口课程要求调整，但一旦进入集成阶段应保持稳定。

## 12. 性能计数与对比方案

### 12.1 硬件性能计数器

至少实现：

- `cycle_count`：CPU 运行周期数；
- `instret_count`：成功退休的指令数；
- `stall_data_count`：数据冒险停顿周期；
- `stall_icache_count`：I-Cache 等待周期；
- `stall_dcache_count`：D-Cache 等待周期；
- `branch_count`：实际执行的分支数；
- `branch_mispredict_count`：误预测次数；
- `icache_hit/miss_count`；
- `dcache_hit/miss_count`（若实现 D-Cache）；
- `interrupt_count` 和 `exception_count`。

计数器可通过仿真层次路径观察，也可映射到只读 CSR 或 MMIO 地址，供测试程序读取。

### 12.2 指标计算

```text
CPI = cycle_count / instret_count
IPC = instret_count / cycle_count
分支预测准确率 = 1 - branch_mispredict_count / branch_count
Cache 命中率 = hit_count / (hit_count + miss_count)
CPU 时间 = cycle_count / 时钟频率
```

MIPS 可作为辅助指标，但不同指令集或不同程序间直接比较 MIPS 容易产生误导，因此建议以 CPI、CPU 时间和相同测试程序的总周期为主要指标。

### 12.3 对比实验矩阵

至少完成以下配置：

| 配置 | Cache | 分支预测 | 目的 |
|---|---:|---:|---|
| 单周期 CPU | 无 | 无 | 大三实验基线 |
| 流水线基线 | 关闭 | 静态不跳转 | 观察流水线本身效果 |
| 流水线 + Cache | 开启 | 静态不跳转 | 分析 Cache 贡献 |
| 完整流水线 | 开启 | 动态预测 | 分析完整设计效果 |

必须尽量保证测试程序、输入数据和功能输出一致；报告中记录时钟频率、存储器延迟、程序指令数、是否包含初始化时间等测试条件。不能只展示“更快”，还要解释停顿和失效的来源。

## 13. 验证方案

### 13.1 验证层次

1. **模块级测试**：ALU、立即数、寄存器堆、微程序 ROM、前递、冒险、预测器、Cache、CSR；
2. **指令级测试**：每条指令至少一个正常用例和边界用例；
3. **相关性测试**：RAW 前递、load-use、连续依赖、存储数据依赖；
4. **控制流测试**：分支、跳转、误预测恢复；
5. **异常中断测试**：溢出、非法指令、中断、`MRET`；
6. **Cache 测试**：命中、缺失、替换、等待、uncached 外设；
7. **系统程序测试**：循环、数组处理、函数调用、访存与外设输出；
8. **综合与下板测试**：时钟、复位、BRAM、引脚、ILA 和外设现象。

### 13.2 自检式 testbench

testbench 不应只生成波形，还应自动判断：

- 最终寄存器值；
- 最终存储器值；
- 退休 PC/指令序列；
- 异常/中断入口和返回 PC；
- Cache 命中/缺失数；
- 分支预测次数和误预测次数；
- 运行是否在最大周期数内结束。

可在程序末尾向约定的 `tohost` 地址写入成功/失败码，testbench 观察该地址后自动输出 PASS/FAIL。

### 13.3 参考模型

建议编写一个只支持本项目指令子集的简单非流水软件参考模型，或使用人工确认的指令结果表。每次退休时比较架构寄存器和存储器状态，可显著降低流水线问题定位难度。若使用现成模拟器，只用于核对公开指令语义，不得复制 CPU 实现代码。

### 13.4 必须保存的证据

- 每类指令的关键波形；
- 三类流水线相关的定向波形；
- Cache hit/miss 和 refill 波形；
- 分支预测正确/错误波形；
- 中断进入和返回波形；
- 溢出异常波形；
- 性能计数器原始数值；
- 综合资源利用率和时序报告；
- 下板照片或不超过 5 分钟的视频。

## 17. 风险与降级方案

| 风险 | 影响 | 预防与降级 |
|---|---|---|
| 微程序控制与流水线边界不清 | 控制信号错位 | 固定为 ID 查表、控制字随指令流水，仲裁器独立 |
| 四项附加功能同时开发 | 集成时间不足 | 严格按基础 CPU→中断→I-Cache→预测→D-Cache 顺序 |
| D-Cache 写回逻辑复杂 | 数据丢失或重复写 | 首版使用 write-through + no-write-allocate |
| Cache miss 与中断冲突 | 状态不精确 | 中断挂起，待老指令/存储访问到安全边界再接受 |
| 误预测与异常同时出现 | PC 重定向错误 | 集中仲裁，并按老指令异常优先处理 |
| 异步中断输入不稳定 | 亚稳态或请求丢失 | 双触发同步并锁存 pending |
| 下板存储器延迟不同 | 仿真正确但硬件错误 | 全部存储接口使用握手协议，不假设固定单周期 |
| 性能数据无法解释 | 报告重点项失分 | 从第一版就加入分类性能计数器 |
| 功能太多导致基础 CPU 不稳定 | 无法验收 | 保留功能开关，随时回退到已验证配置 |

最低可交付版本应包含：五级流水、微程序控制、不少于 16 条指令、三类相关处理、溢出、中断、至少 I-Cache、基础动态分支预测、完整仿真和真实性能数据。D-Cache、定时器中断、返回地址栈和更复杂 Cache 结构作为进度允许时的增强功能。
