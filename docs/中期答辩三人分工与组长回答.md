# 中期答辩三人分工与组长回答

## 1. 答辩目标

中期答辩重点回答以下四个问题：

1. 设计目标是否符合课程要求；
2. 实验思路和设计方案是否恰当；
3. 三人分工是否合理；
4. 进度安排能否保证在小学期内完成。

本项目同时服务于“计算机组成原理课程设计”和“汇编与接口技术课程设计”。两门课程共用同一套 EES-338 计算机系统，但评价对象不同：

- 计组课程评价基于水平微码控制的 RV32I 五级流水 CPU；
- 汇编与接口课程评价 ST7571 LCD SPI 接口控制器、MMIO 接口及 RISC-V 汇编驱动；
- CPU 是汇编程序的运行平台，LCD 控制器是汇编课程的主要接口成果，二者不重复计分。

## 3. 分工合理性说明

三人的任务按照模块边界划分：

| 成员 | 核心对象 | 主要接口 | 验证责任 |
|---|---|---|---|
| 成员 A | 指令集、微码控制、CPU 与 SoC 总体结构 | 流水控制字、CPU 存储接口 | 总体集成与系统闭环 |
| 成员 B | 流水线相关处理和存储等待 | 各级 valid、stall、flush、forward | CPU 核心与综合程序测试 |
| 成员 C | LCD SPI 控制器、MMIO 和汇编驱动 | ready/valid、LCD 寄存器、SPI 管脚 | SPI、控制器和接口测试 |

这种划分具有以下特点：

- 每个人都有明确的硬件或软件设计对象，不是只负责整理文档；
- 模块之间通过事先确定的接口协作，便于并行开发；
- 每个人同时负责自己模块的验证，避免测试全部集中在一人；
- 组长负责接口和系统集成，能够及时处理跨模块问题；
- 三人的成果可以分别在 RTL、testbench、汇编程序和设计文档中追溯。

## 4. 组长对答辩重点问题的回答

### 4.1 设计目标是否符合要求

建议回答：

> 我们的目标符合两门课程要求。计组部分设计一颗基于水平微码控制的 RV32I 五级流水 CPU，基础阶段支持 27 条指令，超过不少于 16 条的要求，并覆盖运算、传送和控制三类指令。设计使用前递、load-use 停顿、指令与数据接口分离、存储握手和分支冲刷处理流水线相关。汇编与接口部分选择 ST7571 LCD 作为主要外设，完成 4 线 SPI 控制器、MMIO 寄存器和 RISC-V 汇编驱动。两门课程使用同一套系统，但计组评价 CPU，汇编课程评价 LCD 接口与驱动，计分内容没有重叠。

### 4.2 实验思路和设计方案是否恰当

建议回答：

> 我们采用自底向上、分层验证的实验思路。CPU 先确定指令语义和控制字，再实现五级数据通路，随后分别处理前递、停顿、存储等待和分支冲刷。LCD 部分把单字节 SPI master、上层初始化控制器、MMIO 接口和汇编驱动分层实现。每一层先做单元测试，再进行 CPU 或 SoC 联调。testbench 不只观察波形，还自动检查寄存器、存储器、退休序列和最终 PASS。这样能够在模块边界定位问题，也能用系统程序证明各模块协同正确。

### 4.3 三人分工是否合理

建议回答：

> 三人的分工按设计对象和接口边界划分。成员 A 负责指令集、微码控制、CPU 总体结构和系统集成；成员 B 负责流水线相关处理、存储等待和 CPU 验证；成员 C 负责 LCD SPI 控制器、MMIO 和汇编驱动。每个人都有设计、实现和测试任务。接口由组长统一维护，联调问题由相关两人共同定位，因此分工既能并行推进，也不会形成无人负责的交界部分。

### 4.4 进度能否保证在小学期内完成

项目当前已经完成。中期答辩建议按实际开发过程说明进度控制方法，不虚构尚未完成的工作。

建议回答：

> 我们把工作拆成基础规格、模块实现、系统联调和结果整理四个阶段，并为每个阶段设置可检查的交付物。第一阶段完成指令表、控制字、流水寄存器和 MMIO 约定；第二阶段三人并行完成 CPU 控制、相关处理和 LCD 接口；第三阶段使用自检 testbench 联调 CPU、存储器和外设；第四阶段整理波形、文档和汇报材料。各模块在进入系统联调前必须先通过自己的单元测试，接口文档由组长统一维护。实际结果表明，该安排已经完成全部项目内容，因此能够保证小学期内交付。

## 6. 进度安排的答辩展示版本

虽然项目已经完成，答辩时仍可用以下阶段表说明当时的计划能够覆盖小学期：

| 阶段 | 主要工作 | 阶段验收物 | 负责人 |
|---|---|---|---|
| 第一阶段 | 明确需求、指令集、控制字、流水寄存器和 MMIO | 设计规格与接口文档 | 成员 A 主责，三人评审 |
| 第二阶段 | 并行实现 CPU 控制、相关处理和 LCD SPI 控制器 | RTL 编译通过，单元测试通过 | A、B、C 分别负责自己的模块 |
| 第三阶段 | CPU 核心测试、LCD 接口测试和 SoC 联调 | 自检 testbench PASS，关键时序可解释 | 成员 B、C 主测，成员 A 集成 |
| 第四阶段 | 完整程序、结果复核和汇报材料 | 可复现实验、文档、PPT 和演示材料 | 三人共同完成，成员 A 汇总 |

进度控制原则：

- 每个阶段都有可以运行或检查的交付物；
- 单元测试通过后才进入系统联调；
- 接口变更同步更新设计文档；
- 每次集成保留可运行基线，出现问题时能够回退比较；
- 汇报材料直接引用已验证的 RTL、testbench、程序和结果文件。

## 7. 组长结束语

> 中期阶段已经完成基础 CPU 和 LCD 接口的核心设计，技术路线与课程要求对应明确。三人的任务按模块边界划分，每个人都承担设计、实现和验证工作。项目采用单元测试、核心测试和系统联调逐层推进，关键接口都有文档和自检标准。当前项目已经完成，说明原定分工与进度安排能够支持在小学期内完成交付。
